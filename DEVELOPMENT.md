# Development build 0.1.0-dev

Not production-ready. Use dummy content only. No live installation has been performed.

## Initial usage (for controlled testing after review)
Create an Experience from the WordPress admin, set the WooCommerce product ID and optional local expiration date, and publish it. Create Experience content entries with the parent Experience ID, local release date and menu order. Publish them. On a dedicated Elementor page use the Shortcode widget with [kmd_experience id="123"] or [kmd_experiences]. Use account-associated paid test orders.

The initial renderer uses non-public custom post types and sanitizes stored HTML without executing shortcodes. It displays all released sections inline. It does not yet provide full Elementor editing of protected entries, private file delivery, comments, manual access, enrollment-relative releases, guest enrollment, notification emails, or duplication. Product IDs are entered manually. Do not upload confidential files to the standard media library.

## Gates before installation
- PHP lint and WordPress/WooCommerce integration tests.
- Validate order pagination and paid/refunded line items with HPOS and legacy order storage.
- Verify non-public post types against REST, feeds, search, XML sitemaps, direct queries, oEmbed, third-party search and Elementor endpoints.
- Ensure dedicated shortcode pages are excluded from all page/CDN caches, including anonymous cache hits. Shortcode-level no-cache headers alone are insufficient.
- Check site timezone boundaries, invalid dates, and DST transitions.
- Review admin capability isolation and test customer accounts.
- Verify rollback and backups before any controlled live test.

Owner has authorized controlled production testing, but this does not make untested code safe to deploy. Do not use actual member material until all access and cache checks pass. No production credentials or customer data are needed in GitHub.

## Update: 0.4.0-dev
Private file delivery and upload controls are now implemented. A host administrator must create a directory outside all web-accessible roots and set KMD_PRIVATE_DIR in wp-config.php to its absolute path. The directory must be writable by PHP, restricted to the service account, and verified against web-server aliases and CDN configuration. Do not use the standard media library for confidential material. Files & Access under Experiences supports uploads by content section ID and manual grants/blocks by WordPress user ID. Grants respect the experience expiration; per-user extensions, file deletion, concurrent upload handling and participant discovery are not yet implemented. Test upload size limits, MIME validation, audio range requests and access revocation on the actual host. The previous limitations above concerning missing upload and manual grant functionality are superseded by this update.

## Update: 0.6.0-dev
Enable private reflections independently on a lesson. Submissions are plain text and require administrator approval under Experiences > Reflections. Replies are one level deep; participant display names are visible. The isolated database table is created on an administrator visit. Ordinary WordPress comments remain disabled on experience content. Current display and moderation limits are 500 approved entries per lesson and 100 recent moderation records; pagination, staff replies without enrollment, privacy export/erasure and retention controls, and reply notifications remain outstanding. Test permissions, nonce validation, SQL queries, moderation, hidden parent replies, expiration and cache isolation on WordPress.

Automatic emails are OFF by default per experience. To enable, enter a published page ID containing the access shortcode, then explicitly enable emails. WordPress cron processes batches of 25 site accounts every five minutes, checking active enrollment before sending. Welcome is sent on discovery; release notices apply to newly released sections within seven days after welcome; closure notices are sent within seven days of expiry. Existing eligible participants can receive welcome mail when enabled. Messages are plain text and not yet customizable. Delivery is not guaranteed by wp_mail; configure and test mail transport and cron. Account scans may be slow on large sites. Unique database options claim each message and a worker lock prevents overlap. Failures reported by wp_mail are retried; an interrupted worker can leave a stale lock or ambiguous send claim requiring manual recovery. No automated reset is implemented yet. Do not enable real emails until test recipients, mail capture, cron, and deduplication are verified. This build has not been installed on the live site.

## Update: 0.7.0-dev
From the Experiences list, Duplicate as draft copies the experience and its sections, preserving written content, order, sharing preferences and custom email wording. Product and email page links are reset, notifications are disabled, and dates are marked unconfigured (access fails closed until a valid date or explicit no-date choice is saved). All copied posts are drafts. Private file records, reflections, participant overrides and notification history are not copied. Review copied written content for links or personal details before publishing. Product, experience, section and page selectors now show names; optional variation ID overrides product selection. Manual access uses an existing user's exact account email. These selectors currently load all eligible posts and may need searchable pagination for large stores. Custom plain-text email subject and body can use {experience}, {section}, {link}, {expiry}; blank fields use defaults. The access page link is appended when missing. Verify duplication rollback, date setup, selectors, template substitution, and email sending in WordPress. Individual extensions, relative dripping, full Elementor editing and the other documented integration/security gates remain pending. No live installation has occurred.

## Update: 0.8.0-dev
Use an Elementor Shortcode widget with [kmd_experience id="123"] for each experience or [kmd_experiences] for the participant dashboard. The shortcode now emits only a public shell and JavaScript fetches member-specific HTML through an authenticated same-origin POST to WordPress admin-ajax.php. Responses have private/no-store cache headers. This reduces exposure through Elementor element caching and public page HTML; it is not a substitute for checking CDN, reverse proxy, AJAX and private file caching. Do not cache admin-ajax.php or admin-post.php responses. Verify the portal on Hello Elementor, desktop/mobile, logged in/out, after switching accounts, and with real cache settings. JavaScript is required. Scoped CSS inherits the surrounding theme. Protected entries themselves still use the native WordPress editor; arbitrary Elementor widgets and shortcodes inside them are not supported. Configure an experience's access page for dashboard links as well as email links. Reflection forms now omit the AJAX-generated referer and use the browser's page referer for return navigation.

Files & Access supports a personal closing date later than a valid finite global expiry. This extends an existing entitlement but does not enroll a user. A grant can be combined with an extension; a deny always takes precedence; leaving the extension blank removes it. Invalid or unconfigured global dates cannot be overridden. Closure emails use the effective expiry and deduplicate per expiry date. A changed date may generate a new reminder. Expiry checks remain server-side for lessons, files and sharing. Automated tests cover extension policy; real WordPress integration, mail delivery and full security checks remain pending. No live deployment has occurred.
